# ADK Agent Analytics Plugin Tables and Views

This skill guides agents on navigating, querying, and extracting insights from BigQuery tables and views generated by the [ADK BigQuery Agent Analytics plugin](https://adk.dev/integrations/bigquery-agent-analytics/).

---

## 1. Data Model Overview

The destination dataset is organized into:
1. **Base Event Table (`agent_events`)**:
   - The single immutable append-only sink for all telemetry rows.
   - **Partitioned** by `DATE(timestamp)` (daily).
   - **Clustered** by `(event_type, agent, user_id)`.
   - Contains raw JSON payloads (`content`, `attributes`, `latency_ms`) and multimodal references (`content_parts`).
2. **Analytical Views (default prefix `v_`)**:
   - 25 strongly typed views that project and flatten event-specific JSON fields into typed columns.
   - Always prefer views over querying `agent_events` directly for standard analysis.
3. **Trace and Span Hierarchy**:
   - OpenTelemetry-compatible distributed tracing via `trace_id` (32-hex), `span_id` (16-hex), and `parent_span_id` (16-hex).
4. **ADK 2.0 Workflow Envelope**:
   - JSON envelope in `attributes.adk` capturing workflow graph nodes, run IDs, routing, agent transfers, and pause/resume pairing keys.

## 3. Base Table vs. Analytical Views

### When to Query the Views (`v_*`):
- **Default choice**: Always start with the view corresponding to your analytical goal.
- **Benefits**:
  - Direct access to typed columns (e.g., `usage_prompt_tokens` as `INT64`, `total_ms` as `INT64`).
  - No need to parse JSON strings with `JSON_VALUE(content, '$.usage.prompt')`.
  - Automatically filters by the appropriate `event_type`.

### When to Query the Base Table (`agent_events`):
- **Full Trace Timeline**: When you need an unbroken, interleaved chronology of all events in a turn or session (`WHERE session_id = '...' ORDER BY timestamp ASC`).
- **Span Hierarchy**: Reconstructing parent-child execution DAGs (`span_id` and `parent_span_id`).
- **Multimodal & GCS Objects**: Accessing `content_parts` array to query images, audio, or signed URLs.
- **Custom Metadata / Tags**: Querying application-specific fields in `attributes.custom_tags` or `attributes.session_metadata`.

---

## 4. Query Best Practices

1. **Partition Pruning (Crucial for Performance & Cost)**:
   - Always include a filter on `timestamp` (e.g., `WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 7 DAY)`).
   - Avoid querying without date boundaries on large production datasets.
2. **Clustering Optimization**:
   - Filter on clustered columns: `event_type`, `agent`, and `user_id`.
3. **Correlating Paused & Resumed Tools**:
   - To match a paused tool (`TOOL_PAUSED`) with its resumption (`TOOL_COMPLETED`), always join on:
     `USING (session_id, user_id, function_call_id)`
4. **Trace Correlation**:
   - Filter by `trace_id` to inspect all operations executed within a single end-to-end conversation turn.
   - Cross-reference `trace_id` with Cloud Trace when deploying on Vertex AI Agent Engine.
