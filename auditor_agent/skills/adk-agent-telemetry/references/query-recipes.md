# BigQuery Query Recipes for ADK Agent Analytics Plugin

This document provides production-ready BigQuery SQL recipes for querying tables and views generated by the ADK BigQuery Agent Analytics plugin.
Replace `your-project-id` and `your_dataset` with your Google Cloud Project ID and configured dataset name.

---

## 1. Trace and Session Flow

### A. Trace Full Timeline for a Single Conversation Turn (`trace_id`)
Use this query to inspect every action in chronological order for a single turn:
```sql
SELECT
  timestamp,
  event_type,
  agent,
  status,
  error_message,
  -- Extract human-readable summary depending on event type
  COALESCE(
    JSON_VALUE(content, '$.response'),
    JSON_VALUE(content, '$.tool'),
    JSON_VALUE(content, '$.text_summary'),
    event_type
  ) AS summary
FROM `your-project-id.your_dataset.agent_events`
WHERE trace_id = 'your-trace-id'
ORDER BY timestamp ASC;
```

### B. Hierarchical Span & Duration Tree
Reconstruct the parent-child caller hierarchy to visualize the execution DAG:
```sql
SELECT
  span_id,
  parent_span_id,
  event_type,
  agent,
  timestamp,
  CAST(JSON_VALUE(latency_ms, '$.total_ms') AS INT64) AS duration_ms,
  COALESCE(JSON_VALUE(content, '$.tool'), 'LLM_CALL') AS operation
FROM `your-project-id.your_dataset.agent_events`
WHERE trace_id = 'your-trace-id'
  AND event_type IN ('LLM_RESPONSE', 'TOOL_COMPLETED', 'AGENT_COMPLETED')
ORDER BY timestamp ASC;
```

## 2. LLM Cost, Token Usage & Cache Efficiency

### A. Token Usage and Context Cache Hit Rate
Analyze token breakdown and prompt caching performance using the `v_llm_response` view:
```sql
SELECT
  model_version,
  COUNT(*) AS total_calls,
  ROUND(AVG(usage_prompt_tokens), 1) AS avg_prompt_tokens,
  ROUND(AVG(usage_completion_tokens), 1) AS avg_completion_tokens,
  ROUND(AVG(usage_cached_tokens), 1) AS avg_cached_tokens,
  ROUND(AVG(usage_thinking_tokens), 1) AS avg_thinking_tokens,
  ROUND(AVG(usage_total_tokens), 1) AS avg_total_tokens,
  ROUND(AVG(context_cache_hit_rate) * 100, 2) AS avg_cache_hit_rate_pct
FROM `your-project-id.your_dataset.v_llm_response`
WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 7 DAY)
GROUP BY model_version
ORDER BY total_calls DESC;
```

### B. LLM Latency & Time to First Token (TTFT)
Measure model response time and streaming responsiveness:
```sql
SELECT
  model_version,
  COUNT(*) AS request_count,
  ROUND(AVG(total_ms), 1) AS avg_latency_ms,
  ROUND(AVG(ttft_ms), 1) AS avg_ttft_ms,
  APPROX_QUANTILES(total_ms, 100)[OFFSET(95)] AS p95_latency_ms
FROM `your-project-id.your_dataset.v_llm_response`
WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 7 DAY)
GROUP BY model_version;
```

## 3. Tool Usage, Latency & Provenance

### A. Tool Performance and Origin Breakdown
Compare invocation volume, average duration, and provenance (e.g., LOCAL vs. MCP vs. SUB_AGENT):
```sql
SELECT
  tool_origin,
  tool_name,
  COUNT(*) AS call_count,
  ROUND(AVG(total_ms), 1) AS avg_latency_ms,
  APPROX_QUANTILES(total_ms, 100)[OFFSET(95)] AS p95_latency_ms
FROM `your-project-id.your_dataset.v_tool_completed`
WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 7 DAY)
GROUP BY tool_origin, tool_name
ORDER BY call_count DESC;
```

### B. Identify Slowest Tools
```sql
SELECT
  tool_name,
  tool_origin,
  COUNT(*) AS executions,
  MAX(total_ms) AS max_ms,
  ROUND(AVG(total_ms), 1) AS avg_ms
FROM `your-project-id.your_dataset.v_tool_completed`
WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 24 HOUR)
GROUP BY tool_name, tool_origin
HAVING executions >= 5
ORDER BY avg_ms DESC
LIMIT 10;
```

## 4. Error & Failure Debugging

### A. Recent Tool Failures
```sql
SELECT
  timestamp,
  agent,
  tool_name,
  tool_origin,
  error_message,
  tool_args,
  total_ms
FROM `your-project-id.your_dataset.v_tool_error`
WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 24 HOUR)
ORDER BY timestamp DESC
LIMIT 20;
```

### B. Recent LLM Failures (Quota, 429s, API Errors)
```sql
SELECT
  timestamp,
  agent,
  error_message,
  total_ms
FROM `your-project-id.your_dataset.v_llm_error`
WHERE timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 24 HOUR)
ORDER BY timestamp DESC
LIMIT 20;
```

### C. Unhandled Agent & Invocation Exceptions
```sql
SELECT
  timestamp,
  event_type,
  agent,
  session_id,
  invocation_id,
  error_message,
  JSON_VALUE(content, '$.error_traceback') AS traceback
FROM `your-project-id.your_dataset.agent_events`
WHERE event_type IN ('AGENT_ERROR', 'INVOCATION_ERROR')
  AND timestamp >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 24 HOUR)
ORDER BY timestamp DESC
LIMIT 10;
```

## 5. Asynchronous Tools & HITL Turnaround

### A. Paused Tool Resumption Duration
Pair each tool suspension (`TOOL_PAUSED`) with its completion (`TOOL_COMPLETED`) to measure how long external jobs took:
```sql
SELECT
  p.session_id,
  p.user_id,
  p.tool_name,
  p.pause_kind,
  p.function_call_id,
  p.timestamp AS paused_at,
  c.timestamp AS resumed_at,
  TIMESTAMP_DIFF(c.timestamp, p.timestamp, SECOND) AS paused_seconds
FROM `your-project-id.your_dataset.v_tool_paused` AS p
JOIN `your-project-id.your_dataset.v_tool_completed` AS c
  USING (session_id, user_id, function_call_id)
WHERE p.pause_kind = 'tool'
ORDER BY paused_at DESC
LIMIT 25;
```

### B. Human-in-the-Loop (HITL) Approval Volume
```sql
SELECT
  event_type,
  tool_name,
  COUNT(*) AS request_count
FROM (
  SELECT event_type, tool_name FROM `your-project-id.your_dataset.v_hitl_credential_request`
  UNION ALL
  SELECT event_type, tool_name FROM `your-project-id.your_dataset.v_hitl_confirmation_request`
  UNION ALL
  SELECT event_type, tool_name FROM `your-project-id.your_dataset.v_hitl_input_request`
)
GROUP BY event_type, tool_name;
```

## 6. Multi-Agent Delegation & Workflows

## 7. Multimodal Payloads & GCS Offloading

### A. List Offloaded Images and Media Files
```sql
SELECT
  timestamp,
  event_type,
  agent,
  part.mime_type,
  part.object_ref.uri AS gcs_uri
FROM `your-project-id.your_dataset.agent_events`,
UNNEST(content_parts) AS part
WHERE part.storage_mode = 'GCS_REFERENCE'
  AND part.mime_type LIKE 'image/%'
ORDER BY timestamp DESC
LIMIT 20;
```

### B. Generate Signed URLs for Offloaded Artifacts
*(Requires Cloud Resource Connection configured as authorizer)*
```sql
SELECT
  timestamp,
  event_type,
  part.mime_type,
  part.object_ref.uri AS gcs_uri,
  STRING(OBJ.GET_ACCESS_URL(part.object_ref, 'r').access_urls.read_url) AS signed_url
FROM `your-project-id.your_dataset.agent_events`,
UNNEST(content_parts) AS part
WHERE part.storage_mode = 'GCS_REFERENCE'
ORDER BY timestamp DESC
LIMIT 10;
```

## 8. AI-Powered Automated Root Cause Diagnosis

Reconstruct context from a failed conversation session and pass it directly to Gemini within BigQuery to identify the root cause:
```sql
WITH FailedSession AS (
  SELECT session_id
  FROM `your-project-id.your_dataset.agent_events`
  WHERE status = 'ERROR' OR error_message IS NOT NULL
  ORDER BY timestamp DESC
  LIMIT 1
),
SessionHistory AS (
  SELECT
    e.session_id,
    STRING_AGG(
      CONCAT('[', CAST(e.timestamp AS STRING), '] ', e.event_type, ' (', COALESCE(e.agent, 'unknown'), '): ',
             COALESCE(TO_JSON_STRING(e.content), e.error_message, '')),
      '\n' ORDER BY e.timestamp ASC
    ) AS full_history
  FROM `your-project-id.your_dataset.agent_events` e
  JOIN FailedSession f ON e.session_id = f.session_id
  GROUP BY e.session_id
)
SELECT
  session_id,
  AI.GENERATE(
    ('Analyze this agent execution trace and determine why the session failed. Provide root cause and resolution recommendation:\n\n', full_history),
    endpoint => 'gemini-flash-latest'
  ).result AS root_cause_explanation
FROM SessionHistory;
```
